# Spike A, A4 evidence (2026-11-14)

Setup: Rancher v2.15.3 (single node, Docker) on the temporary `rancher-spike` instance,
configured by the spike's `configure_spike_rancher.py`. The `sre-agent` user holds only
the global role `user-base` and the cluster role `agent-readonly` on `local` (get, list
and watch on pods, pods/log, events, namespaces, deployments, replicasets, services and
nodes; nothing on Secrets). Its API token expires one day after first use and stays in
the macOS Keychain.

MCP server: `rancher-ai-mcp` v1.2.0-alpha.5 (commit 46f49c7e4e296e003b01c05ab97fb918c733cb49),
built locally with `package/Dockerfile` (`go mod verify`: all modules verified), run in
stdio mode by the spike's `rancher-mcp.sh`. TLS to Rancher is verified against Rancher's
own CA through `SSL_CERT_FILE`; the leaf certificate names the instance's public IP, so no
`--insecure` is needed. Client: the spike's `mcp_probe.py` (MCP 2025-06-18 over stdio).

| Check | Call | Result |
|---|---|---|
| Server starts in stdio mode | `initialize`, `tools/list` | `rancher mcp server v1.0.0`, protocol 2025-06-18, 53 tools |
| Read: namespaces | `listKubernetesResources` cluster=local, kind=Namespace | 20 namespaces, all Active |
| Read: pods | `listKubernetesResources` cluster=local, namespace=cattle-system, kind=Pod | 15 pods with phase, readiness and restarts |
| Least privilege: Secrets | `listKubernetesResources` kind=Secret | `isError: True`: secrets is forbidden: User "u-6m7b9" cannot list resource "secrets" in API group "" in the namespace "cattle-system" |
| Write refused by Rancher | `patchKubernetesResource` on pod `default/spike-a-write-test-does-not-exist` (approved by the human; the tool PATCHes without a GET, so 403 means no right and 404 would mean the right exists; nothing can change either way) | `isError: True`: pods "spike-a-write-test-does-not-exist" is forbidden: User "u-6m7b9" cannot patch resource "pods" in API group "" in the namespace "default" |
| Second layer: `--read-only` | `tools/list` with `mcp serve --stdio --read-only` | 29 tools, no create, patch, scale, update or move tool |

Findings:

- Stdio mode exists only from v1.2.0-alpha; the stable v1.1.1 has HTTP mode only.
- No public image: the release workflow pushes to SUSE's private registry, so we build it.
- The server has no delete tool; its 24 write tools create, patch, scale, update and move,
  each with a "Plan" variant that only returns the JSON.
- 52 of 53 tools carry no MCP annotations (`readOnlyHint` is set only on
  `createProjectRoleTemplateBindingPlan`), so a client cannot tell reads from writes by
  annotation. Use `--read-only` and Rancher's RBAC instead.
- In stdio mode the server trusts the system store only (no CA option); `SSL_CERT_FILE`
  works in its Linux container. On macOS a native build would need the CA in the Keychain.
- The server reports its version as v1.0.0 whatever the release.

The spike's scripts (`configure_spike_rancher.py`, `rancher-mcp.sh`, `mcp_probe.py`,
`setup_gateway.py`, `teardown.py`) ran from the git-ignored `build/spike-a/` and land in a
follow-up pull request under `tools/spikes/spike-a/`.
